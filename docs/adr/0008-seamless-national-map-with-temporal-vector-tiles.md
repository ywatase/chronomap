# ADR 0008: 全国シームレス地図と時系列ベクタータイル

Date: 2026-10-11

Status: Accepted

Superseded by: なし

## Context

2026-10-11時点のビューアーは、地域データセット（巨椋池、利根川など）を選んでから作成済みスナップショット年を切り替える構成である。収録は7地域・約50地物・約98KBで、その多くは少数の頂点による手描きの概略面・概略線である。UIシェルは教材・教材パック・カタログ・印刷・フィードバック導線を前提に組まれ、`web/src` のおよそ半分を占める。

UXの参照としている全国地番マップ（chiban.koaza.net）は、全国を1枚につないだ地図をズームとテーマ別レイヤーで見せ、表示状態をURLで共有する。Chronomapの体験はこれと根本的に異なり、地域を選ぶ前提、データ密度の低さ、教材向けUIのいずれも原要求（[初期プロンプト](../original/first_prompt.txt)）の「当時の海岸線・湖・河川、城・古戦場、国・勢力圏を現在の地図で見比べる」から離れている。

データ契約（[ADR 0004](0004-versioned-historical-features.md)、[ADR 0005](0005-normalized-data-package.md)、[ADR 0006](0006-possible-time-and-parallel-hypotheses.md)）、fail-closedな公開投影（[ADR 0007](0007-fail-closed-public-projection.md)）、MapLibre GL JSと地理院タイル（[ADR 0003](0003-maplibre-and-gsi-basemap.md)）は、この体験にもそのまま使える。

## Decision

1. **全国シームレス地図を本体とする。** 利用者は地域データセットを選ばない。初期表示は全画面の地図で、全公開地物をズームと年で絞り込んで表示する。地域データセットは、編集・出典・権利を管理する単位として残す（[ADR 0001](0001-single-shared-web-application.md)は維持する）。
2. **時系列ベクタータイルで配信する。** 公開投影の後段で、全データセットの公開FeatureVersionを1つ以上のPMTilesへ統合する。各地物は、可能な活動期間（[データモデル](../data/model.md)の `start.earliestYear` から `end.latestYear` まで）を表す数値属性 `from_year`・`to_year`（開いた端は番兵値）と、`entity_id`、`feature_version_id`、`dataset`、`theme` を持つ。詳細・出典・不確実性はタイルに入れず、`feature_version_id` で引く静的JSON索引から遅延読込する。
3. **年はレイヤーではなくフィルタで表す。** 時代別にレイヤーを作らない。選択年 `y` に対し、MapLibreのfilter式で可能期間に `y` を含む地物だけを描画する。スナップショット間の形状を補間・合成しない（[ADR 0006](0006-possible-time-and-parallel-hypotheses.md)の可能期間と並行仮説の扱いを維持する）。
4. **レイヤーはテーマ別に分ける。** 海岸線・海域、湖沼、河川・水路、国・郡、勢力圏、城郭、古戦場、集落・街・港、歴史地図ラスター（旧版地形図など）を基本とし、各テーマを個別に表示・非表示にできる。
5. **時代密度はタイムラインで扱う。** 年スライダーは非線形の目盛り（例: 戦国〜江戸初期を拡大）と、収録イベントの目盛りを持てるようにする。目盛りは収録データから導出する。
6. **データは既存の公開データセットの取り込みを主とする。** 手描きの概略形状は、取り込めるデータがない対象に限定する。取り込みでも、Source・Evidence・権利・不確実性を既存の5ファイル契約に変換し、公開投影の検証を通す。
7. **ビューアーのUIを作り直す。** 全画面の地図、折りたためる左パネル（レイヤー・検索・凡例・表示設定）、下部の年スライダー、クリックで詳細・出典・不確実性を表示するパネル、`#zoom/lat/lng` 形式のURLハッシュと年を含む状態共有で構成する。教材・教材パック・カタログ・価格・フィードバックのコードは新しいビューアーに持ち込まない。

## Alternatives

- **現行UIの段階的改善**は、地域の選択を前提とする状態管理、URL形式、UIシェルを全面的に書き換えることになり、作り直しより費用が大きいため採用しない。
- **Google Maps Platform**は、独自ベクターの年フィルタ・スタイル制御の自由度が低く、利用規約と従量課金に依存するため採用しない。
- **時代ごとの事前生成レイヤー**は、年の粒度を固定し、時代密度の差に応じてレイヤー数が増えるため採用しない。
- **GeoJSONのままクライアントで絞り込む**構成（[ADR 0002](0002-static-client-side-mvp.md)）は、全国規模の行政界・河川・旧村データで配信量と描画量が破綻するため置き換える。
- **PostGIS/タイルサーバー**は、静的ホスティングで要件を満たせる間は導入しない。PMTilesはHTTP Range要求で配信でき、サーバーを持たずに済む。

## Consequences

- 公開ビルドに、PMTiles生成（tippecanoe等）と詳細JSON索引の生成が加わる。生成物は決定的であることを検証する。
- 取り込む外部データごとに、ライセンス、出典表記、改変可否を取り込み前に確認し、Sourceの権利情報へ記録する。条件を満たさないものは取り込まない。
- 既存の7地域データは新しいビューアーに統合して表示を続ける。手描き形状の精緻化よりも網羅を優先する。
- 教材・教材パック・カタログ・価格・フィードバックの既存コードは、新ビューアーへの切替後に削除するか、別ディレクトリへ隔離する。
- 中国・世界も同じパイプラインに載せ、地域の追加はデータの追加で行う。
