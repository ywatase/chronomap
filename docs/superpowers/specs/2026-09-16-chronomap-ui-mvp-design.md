# Chronomap UI MVP 設計仕様

作成日: 2026-09-16
状態: Proposed

## 目的

Chronomapの最初の静的Web SPAを、合意済みの[プロダクト概要](../../product/overview.md)、[アーキテクチャ概要](../../architecture/overview.md)、[歴史データ規範モデル](../../data/model.md)に接続する。利用者が、公開済みの歴史FeatureVersionを単年で絞り込み、地図またはテキスト一覧から選択し、対象の説明、時間、不確実性、出典、権利を確認できることを最初の動作目標とする。

今回の利用者優先順位は、PC大画面とスマートフォンを同等とする。地図だけに依存せず、キーボード、スクリーンリーダー、背景地図障害時にも同じ歴史情報へ到達できる構成にする。

## 範囲

### 含めるもの

- ViteとTypeScriptで構成する静的SPAの最小実装
- 公開バンドルの`dataset.json`、`entities.json`、`sources.json`、`evidence.json`、`feature-versions.geojson`の読込
- 単年の年代操作。年入力、前後移動、BCE/CE表示、可能期間との重なりの説明
- 地図と同期したテキスト地物一覧
- 地図上のFeature選択、重複候補の選択、一覧からの選択
- デスクトップの地図＋サイドバー、モバイルの地図＋一覧／詳細タブ
- Entity、FeatureVersion、時間、不確実性、Evidence、Source、権利の詳細表示
- 並行仮説の同格表示とラベル表示。優先順位や推奨仮説は表示しない
- 初期読込、利用可能、該当なし、読込失敗、再試行、背景地図失敗の状態表示
- GSI背景地図の帰属表示と、背景地図なしでも動作する一覧・詳細導線
- キーボード操作、フォーカス移動、支援技術向け状態通知
- 合成fixtureを使ったブラウザ動作確認。実在の歴史記録は追加しない

### 含めないもの

- ブラウザ上のデータ編集、ログイン、サーバーAPI、リアルタイム共同編集
- 複数Datasetの切替、検索、集計、ブックマーク、共有URL
- 検索のための追加インデックスやPMTiles
- 実在の巨椋池データの制作・公開
- 背景地図の代替プロバイダ。MVPではGSIの利用条件を満たす範囲に限定する

## アプローチ比較

### A: Vite＋TypeScript（採用）

フレームワークを増やさず、状態・ドメインロジック・MapLibre境界を小さなモジュールに分ける。SPAとしての開発サーバーと本番静的出力はViteに任せる。

- 長所: 依存が少なく、Map Adapterを直接テストでき、初回の動作までが短い
- 長所: Pythonのデータ契約とブラウザコードの責務を分離しやすい
- 短所: コンポーネント規約と状態更新をプロジェクト側で明示する必要がある

### B: React＋Vite

画面状態とパネルをReactコンポーネントで管理する。

- 長所: 将来の複数Dataset、ルーティング、複雑なパネル状態に拡張しやすい
- 短所: MVPのための依存と抽象化が増え、MapLibreとのライフサイクル境界が重くなる

### C: HTML＋ES Modulesを直接配信

ビルドツールなしで静的HTMLを配信する。

- 長所: 最短で画面を開ける
- 短所: 型検査、CSS管理、テスト、アセット分割が弱く、後の機能追加で再構成が必要になる

Aを採用する。MVPの画面数と状態数には十分で、Bの抽象化コストを払わずに将来のMap Adapter・Temporal Filter境界を保てるためである。

## 利用者フロー

1. SPAがDatasetの公開バンドルを読み込む。
2. 読込中は対象Dataset名と進行状態を表示する。操作可能なコントロールは無効化する。
3. 読込成功後、初期年を決め、可能期間がその年と重なるFeatureVersionだけを表示する。
4. 利用者は年入力、前の年、次の年で単年を変更する。年変更後も地図の中心・ズームと選択対象は維持する。
5. 地図またはテキスト一覧からFeatureVersionを選択する。複数候補がある場合は候補一覧を経由する。
6. 選択するとMetadata Panelを開き、Entityと選択中のFeatureVersionを分けて表示する。
7. パネルを閉じると、デスクトップでは選択した地物に、モバイルでは詳細を開いたボタンにフォーカスを戻す。
8. 年変更で選択中のFeatureVersionが対象外になった場合、選択を解除し、その理由を短い状態通知で示す。

## レスポンシブ構成

### 共通

画面は`header`、`main`、`footer`のランドマークで構成し、`main`内にDataset見出し、年代操作、地図、地物一覧、詳細領域を置く。最初に「本文へ移動」リンクを表示し、背景地図の帰属は常時見えるフッター領域に置く。

### PC大画面

- 上部: Dataset名、説明、現在年、BCE/CE表記、前後移動、年入力
- 中央: 地図を主領域（おおむね2/3）、右側にテキスト一覧と詳細パネルを持つサイドバー
- 一覧と詳細は同じサイドバー内で切り替え、選択中のFeatureVersionを常に強調する
- 地図上の選択は一覧と同期し、候補が複数ならサイドバー上部に候補を列挙する

### スマートフォン

- 上部: Dataset名と年代操作。年入力は数字キーボードを利用できる入力欄にする
- 地図は画面上部の主領域とし、下部に「地物一覧」「詳細」のタブを置く
- 初期タブは地物一覧。地物を選ぶと詳細タブへ切り替え、詳細には一覧へ戻るボタンを置く
- 複雑なドラッグ式Bottom Sheetは使わず、通常の文書フローと`tabpanel`で実装する
- 地図が利用できない場合も一覧タブと詳細タブは通常どおり操作できる

## 年代操作と表示

内部値は規範モデルに従う天文学的年番号の整数とする。選択年`Y`に対して、FeatureVersionの可能活動期間が`Y`と重なる場合だけ表示する。開区間は無限端として扱い、境界は両端を含む。

初期年は次の順序で決める。

1. `Dataset.temporalExtent.start.latestYear`があれば使う
2. なければ`Dataset.temporalExtent.end.latestYear`を使う
3. どちらもなければ`0`を使う

その値がDatasetの可能範囲外の場合は、可能範囲に含まれる最近の有限年へ寄せる。利用者向け表示は、内部の天文学的年番号を次の規則で変換する。

- `year <= 0`: `1 - year` BCE（内部`0`は1 BCE）
- `year >= 1`: `year` CE

表示には「確定した在年ではなく、可能活動期間が選択年と重なる版を表示する」という説明を常設する。`precision`、`qualifier`、開区間はFeatureVersionの詳細で人間可読に示す。

## 地図・一覧・並行仮説

Map AdapterだけがMapLibre GL JSを参照する。アプリケーション状態とTemporal FilterはMapLibreの型やイベントを知らず、表示対象FeatureVersionの配列をMap Adapterと一覧に渡す。

一覧の各項目は、FeatureVersionのラベル、Entityのラベル、形状種別、時間の要約、主要な不確実性バッジを持つ。ラベルは`defaultLanguage`を優先し、なければ規範モデルの辞書順フォールバックを使う。

同じEntityに属する並行仮説は一つのグループとしてまとめ、各FeatureVersionの`hypothesisLabel`、期間、形状、不確実性を個別に表示する。仮説間の優先順位は付けない。地図では、Entityの色だけに意味を持たせず、仮説は線種・境界線・パターンなど色以外の差も持たせる。色、透明度、線種だけで不確実性を伝えず、一覧と詳細のテキストを正規の説明とする。

地図上で重なるFeatureが複数返った場合は自動で一つを選ばず、同地点の候補一覧を表示する。キーボード利用者は同じ候補一覧をテキストから操作できる。

## Metadata Panel

詳細は次の順序で表示する。

1. **HistoricalEntity**: 名称、対象種別、時代をまたぐ説明
2. **選択中のFeatureVersion**: 版の名称、説明、geometry種別、表示中の期間
3. **不確実性**: `temporal`、`location`、`geometry`、`identity`の4次元を個別に表示し、評価、理由、Evidence参照を示す
4. **Evidence**: `supports`、`locator`、noteを表示し、参照Sourceへ移動できるようにする
5. **Source**: citation、title、creators、publishedYear、URL、accessedDate、rightsを表示する
6. **権利**: FeatureVersion、Dataset、参照Sourceのstatus、attribution、termsを区別して表示する

`restricted`または`unknown` Sourceのcitation-only利用は、公開バンドルに存在する固定の安全なnoticeをそのまま表示し、資料本文を表示しない。GSIの帰属と利用条件はSourceとは別に、地図フッターで常時確認できるようにする。

## 状態とエラー

UI状態は次のいずれかを明示する。

| 状態 | 表示 | 利用可能な操作 |
| --- | --- | --- |
| 初期ロード中 | Dataset名、読込中の対象、進行説明 | なし。必要ならキャンセルではなく待機を示す |
| 利用可能 | 地図、年代操作、一覧 | すべて |
| 該当なし | 選択年に該当するFeatureVersionがない説明 | 年変更、一覧確認 |
| 選択解除 | 年変更で選択版が対象外になった説明 | 年変更、一覧選択 |
| データセット失敗 | 対象、原因の要約、再試行可否 | 再試行 |
| 背景地図のみ失敗 | 地図背景の障害、歴史レイヤーと一覧は継続 | 再試行、一覧・詳細 |
| 再試行中 | 再試行処理中の通知 | 重複再試行を防止 |

公開バンドルの必須ファイルが一つでも読めない場合は、そのDatasetを利用可能と扱わない。将来複数Datasetを扱うときは、失敗したDatasetだけを一覧から隠し、他Datasetは継続する。エラーの内部診断コードは開発者向けに保持し、利用者向けには対象、原因、次に可能な操作を優先して示す。

## アクセシビリティ

- 全てのコントロールをTab移動で到達可能にする
- 年入力、前後移動、タブ、候補一覧、閉じる・戻るに可視フォーカスを持たせる
- 地図以外に同じ地物を選べる一覧を提供する
- 読込、該当なし、選択解除、失敗、再試行完了を`aria-live`で通知する
- 詳細領域は適切な見出し階層を持ち、モバイルの詳細タブは`tabpanel`として関連付ける
- パネルを閉じたとき、開く操作を行った要素へフォーカスを戻す
- 色だけで地物種別、仮説、不確実性を区別しない
- 地図が描画できなくても、一覧・詳細・出典確認を完了できる
- コントラスト、キーボード操作、ズーム時のレイアウト崩れを受入テストで確認する

## データフローとモジュール境界

```text
static public bundle
       ↓
PublicBundleLoader ──→ immutable AppData
       ↓
TemporalFilter(selectedYear)
       ↓
VisibleFeatureVersions
       ├──→ MapAdapter (MapLibre)
       ├──→ FeatureList
       └──→ MetadataPanel
```

実装では次の境界を保つ。

- `PublicBundleLoader`: 5ファイルを相対URLから読み、公開バンドルの必須構造を確認する。authoring packageを直接読み込まない
- `TemporalFilter`: 年の重なり判定と初期年計算を純粋関数として提供する
- `AppState`: 読込、選択年、表示Feature、選択Feature、UI状態を一箇所で管理する
- `MapAdapter`: MapLibreのsource、layer、クリックイベント、背景地図エラーをUI向けイベントへ変換する
- `FeatureList`: 地図と同じ表示Featureを、キーボードで選択可能なテキストとして表示する
- `MetadataPanel`: 選択中Featureから参照を辿り、EntityとVersionを分けて表示する
- `UiShell`: レスポンシブレイアウト、タブ、live region、フォーカス管理を担う

## 静的配信

デモは合成公開バンドルを静的アセットとして配信する。ビルド時にauthoring fixtureから`chronomap-data build-public`で生成した内容と、Webアプリが読むアセットの一致をテストする。ブラウザにはprivate FeatureVersionや未到達のSourceを渡さない。実データを追加するときも、authoring packageをCIまたは公開前処理で検証・投影してから静的アセットへ配置する。

## テストと受入条件

### ロジックテスト

- 天文学的年番号、BCE/CE表示、開区間、境界を含む単年判定
- 初期年計算と可能範囲外の補正
- 言語フォールバック、EntityとVersionの表示分離
- 並行仮説のグループ化と優先順位なしの表示データ
- 選択Featureの年変更時解除、候補選択、フォーカス復帰
- 読込失敗、背景地図失敗、再試行の状態遷移

### ブラウザ受入テスト

- 合成公開バンドルを読み込んで初期画面が利用可能になる
- 年を変更すると一覧と地図が同じFeature集合になる
- 一覧選択と地図選択が双方向に同期する
- モバイル幅で一覧／詳細タブをキーボード操作できる
- 詳細に出典、不確実性、権利が表示される
- private IDやprivate内容がブラウザ配信アセットに含まれない
- 背景地図を失敗させても一覧と詳細が利用できる
- 読込失敗時に再試行でき、例外スタックを画面に表示しない

### 受入基準

1. PCとスマートフォンの両方で、公開合成データの読込から地物詳細確認まで完了できる。
2. 単年を変更すると可能期間の重なりに従って、地図と一覧が同じ内容へ更新される。
3. 地図を使えなくても、一覧から選択して同じMetadata Panelを確認できる。
4. 並行仮説はラベル付きで同格に表示され、手動の優先順位は存在しない。
5. 出典、Evidence、4次元の不確実性、権利が本文複製なしで確認できる。
6. 読込・検証・背景地図の失敗が対象と次の操作を伴って表示される。
7. キーボード操作とフォーカス復帰が主要フロー全体で成立する。
8. 静的出力は、既存のデータ契約とfail-closed公開投影を迂回しない。

## 次段階への境界

この仕様の後に、実装計画を次の順で作る。

1. Webプロジェクトと公開fixtureの静的配信を構成する
2. PublicBundleLoaderとTemporalFilterを実装する
3. FeatureListとMetadataPanelを実装する
4. MapAdapterとGSI帰属を実装する
5. レスポンシブUiShell、状態表示、アクセシビリティを実装する
6. ブラウザ受入テストと公開アセット整合性検査を追加する

実データ制作、公開ホスティング、PMTiles、API化はこの縦切りの受入後に別タスクとして判断する。
