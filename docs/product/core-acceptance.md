# Chronomap コア機能受け入れ基準

作成日: 2026-10-03  
対象: 原要求へ戻すための日本版コア機能。価格・相談導線の受け入れ基準ではない。

## 目的

この文書を、原要求と実装の差分を判断するための基準にする。原要求は[保存された初期プロンプト](../original/first_prompt.txt)にあり、現在の構成判断は[ADR](../adr/README.md)にある。価格カード、相談文、メール下書き、決済はコア機能の達成条件に含めず、以後のコア監査が終わるまで追加しない。

## 原要求の要約

利用者が、現在の地図上で歴史上の水域・河川・海岸線・湖沼、城・古戦場・集落・街・港、国・勢力圏を年代ごとに見比べ、根拠と不確実性を確認できることを目指す。日本を最初の対象とし、中国史・世界史は共通Webアプリへデータセットを追加して拡張する。

「古地図」は、古い地図画像を必ず転載するという意味に固定しない。出典と権利が確認できる場合は歴史地図アセットを重ね、そうでない場合は出典付きの概略geometryとして明確に区別する。精密さを装わないことを受け入れ条件に含める。

## 優先順位

### P0: 1地域を信頼して調べられる

- allow-list済みの公開データセットを読み込める。
- 現在の地図と歴史地物を同じ地理範囲で重ねられる。
- 年代または可能期間で表示を切り替えられる。開いた期間、概略年、並行仮説を単一年の事実へ丸めない。
- 点、線、面を表示でき、選択した地物の名称、説明、時間、geometry、同一性を確認できる。
- 各主張からEvidence、Source、Rightsへ到達でき、時間・位置・形状・同一性の不確実性を表示できる。
- 背景地図が失敗しても、歴史データ、根拠、共有URL、文章レポートを可能な範囲で利用できる。
- デスクトップ、390×844スマートフォン、キーボード、reduced-motionで操作できる。

### P1: 日本の主要な歴史地理を増やせる

原要求に挙げられた題材を、単なるカード数ではなく、次のデータ種別の組み合わせとして検証する。

| 種別 | 規範のentity type | 受け入れ条件 |
| --- | --- | --- |
| 水域・海岸・河川・街道・境界 | `waterbody`, `coastline`, `watercourse`, `route`, `boundary` | 時代付きgeometry、根拠、4次元不確実性を持つ |
| 城・史跡・集落・街・港・古戦場 | `fortification`, `archaeological-site`, `settlement`, `port`, `battlefield` | 代表点または範囲を、精度の限界とともに表示する |
| 国・勢力圏 | `polity`, `sphere-of-influence` | Polygon/MultiPolygon、時代境界、仮説ラベル、凡例と表示切替を持つ |

現時点の公開データは5地域、24 FeatureVersion、17 Entity、6 lessonである。巨椋池、利根川東遷、平城京、安土城・琵琶湖東岸、鬼怒川・小貝川はいずれもパイロットであり、日本全体の網羅ではない。地域ごとの公開到達性と不足するEntity typeは、[日本公開データ・カバレッジ監査](japan-coverage-matrix.md)を正本のスナップショットとする。次に候補とする題材は、石山本願寺、小氷期の海進、古大阪湾、および原要求に照らして不足している港・古戦場・`polity`である。

新しい地域を「完了」と呼ぶ条件は、次をすべて満たすこととする。

1. 主要な水域または交通・地形の関係を1つ以上持つ。
2. 城・集落・港・古戦場などの人間活動の地点または範囲を1つ以上持つ。
3. 可能なら境界・国・勢力圏を1つ以上持つ。無い場合は、資料上まだ公開できない理由を監査記録に残す。
4. 各FeatureVersionが公開可能なSource/Evidence、Rights、4次元不確実性へ到達できる。
5. 現在地図、年代切替、詳細、比較または共有、lesson/E2Eのいずれか必要な導線を再現できる。

### P2: 領域表現を実用にする

スキーマにはすでに `boundary`、`polity`、`sphere-of-influence` が定義されている。未達なのは、実データと表示上の意味である。領域の縦切りでは、次を実装・検証する。

- Polygon/MultiPolygonを地図上で線・面として表示し、点・線と凡例で区別する。
- Entity typeを日本語・英語で表示し、領域だけを表示／非表示にできる。
- 時代、仮説グループ、概略復元であることを詳細パネルと印刷レポートに残す。
- 境界線を確定した国境として表示せず、位置・形状・同一性の不確実性を明示する。
- 隣接領域、重なる仮説、空のgeometry、巨大な頂点数、非有限座標をfail-closedにする。

### P2: 古地図表現を検証する

現状は地理院タイルを現在地図として使い、歴史geometryを重ねている。古地図画像や歴史地図タイルはまだ実装していない。導入する場合の受け入れ条件は次のとおり。

- 公開・利用条件を確認できる日本の1地域のアセットを1つ選ぶ。
- 画像またはタイルの出典、権利、取得日、加工範囲を表示する。
- 現在地図、歴史geometry、古地図アセットを個別に表示／非表示・透明度変更できる。
- アセットが取得できない場合も、現在地図・歴史geometry・根拠は使える。
- 古地図の画像が精密な測量図でない場合、その限界とgeoreferenceの誤差を表示する。
- 外部URLを無検証で公開バンドルへ取り込まず、再現可能なローカルまたは明示的な公開URLとして扱う。

## 検証ゲート

コア機能の実装ごとに、次を記録する。

1. データ: `validate --profile public`、監査Markdown、公開bundleの差分。
2. ドメイン: 年代、geometry、領域、仮説、出典境界のunit test。
3. UI: 1440×900／390×844、キーボード、失敗復帰、横overflowのPlaywright。
4. 表現: 現在地図・歴史geometry・古地図アセットの凡例と不確実性をスクリーンショットで確認。
5. 非退行: 既存の教材・印刷・QR・下書き・相談文の境界を壊さない。

価格、相談、決済を次に進める条件は、少なくともP1の日本データ縦切りと、P2の領域または古地図の1縦切りを、実データと出典付きで完了してから再評価する。
