# Final Fix E: Draft 2020-12 temporal integer semantics

## Change

Temporal semantic validation now recognizes precisely the values accepted by
Draft 2020-12's `integer` type after JSON loading: non-boolean Python
integers and finite integral Python floats. Integral floats are normalized to
Python integers before boundary ordering and possible-range/hypothesis
comparisons, so comparison does not depend on float coercion or fixed-width
integer limits. Boolean, non-integral, and non-finite values do not qualify as
semantic years; structural validation and JSON loading continue to reject
those invalid inputs before semantic validation runs.

## TDD evidence

The new full-facade regressions were run before the production change. Four
failed as expected on the prior helper, with no diagnostics produced for:

- a reversed `10.0`/`5.0` boundary;
- a reversed possible range using `10.0` and `5.0`;
- non-overlapping hypothesis alternatives whose moved range used integral
  decimal years; and
- a reversed finite `1e308`/`-1e308` range accepted by the schema.

The BCE/open-boundary regression remained valid before and after the change;
it protects astronomical year numbering and inclusive possibility-first
overlap at year `-3`.

## Regression coverage

- complete loader/schema/semantic facade coverage for decimal boundary and
  possible-range diagnostics, including exact files and pointers;
- deterministic, non-duplicated hypothesis diagnostics for each member;
- `null` start/end boundaries, negative BCE integral decimals, and inclusive
  endpoint overlap; and
- extremely large finite integral floats without overflow or precision
  exceptions.

## Remaining concerns

JSON decimal notation is parsed as an IEEE-754 float by Python's standard
decoder, so semantic normalization intentionally follows the parsed value—the
same value presented to the Draft 2020-12 validator. This is the required
schema-consistent behavior; preserving an original numeric lexeme would need a
different parser contract.
